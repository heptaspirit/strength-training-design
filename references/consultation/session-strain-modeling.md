# 单次训练应激模型

> 依据：基于 Foster 等 (2001)、Seals 等 (1983)。模型结构、全部系数与阈值均为项目自建工程取值，**未标定**；标定方法见 `references/consultation/srpe-calibration.md`。
> 本文件描述的是**基线层**（通用、可复用于任何训练者、不含任何人的实测数值）。使用者按自己数据调整的那一层见 `references/consultation/individual-calibration.md`。

## 0. 它是审计器，不是预测器

**这一节先于所有技术内容。** 读错读法，后面所有数字都会被用反。

模型是**称重秤**，不是温度计：刻度可以校准、可以漂移、可以重设，但"这个杠铃比那个重"在秤上是事实；它测不出"今天会不会累"。

### 0.1 三类正当用途

| 用途 | 依赖 | 读法 |
|---|---|---|
| **排除法**——秒级刷掉违规落点 | 只要同代码算出的比值 | 结果交训练学规则裁决，模型不生成候选 |
| **单日内部排序**——哪个动作更贵、谁排在谁后面会崩 | 纯结构，参数无关 | 同一节课内部比较 |
| **疲劳账本**——解释「这天为什么重」 | 逐动作可拆 | 账本可审计、可复算 |

### 0.2 硬禁令

1. **不做跨课型的比较——数值和排序都不做。** 「峰值周是 W3 不是 W7」「这周比上周重多少」这类结论**不成立**——它要求 A 在不同课型间可比，而 A 的累加结构做不到这件事。三组不同参数给出同一对比 2.0x / 2.4x / 3.9x 三种幅度：**结构稳、幅度不稳**。

   实测把这条推得更远：**跨课型连排序都不可靠**。8 节课（4 课型 × 2 周）里，模型把一个课型排成 A 最低，实测 AU 排第二（见 §4.2）——因为 A 不登记局部代价，大肌群高组数课被系统性低估。**A 的有效比较范围是同一课型内部**；跨课型要排序，用 sRPE 或 AU，不用 A。
2. **不把「A → sRPE」换算当主要用途。** 这个换算需要一个常数 k，而它在原理上就断了：Foster AU = sRPE × 实际时长，分子里的时长项由训练者自主控组间歇决定，模型不预测它。实测同一套动作结构下实际时长 55 vs 66min（+20%），AU 随之差 31%，而模型 A 只差 3%——**差值全在模型看不见的那一项里**。sRPE 的正当用途是**漂移检测**（同课型固定结构下偏离基线 >1 档 = 有变化），不是预测。
   **课型系数**：若实测/模型时长的比值**课型内稳定、课型间偏**（如某课型恒为 0.7、另一个恒为 1.1），那不是计时问题，是模型对该课型的时长估计有系统性偏差。处置是在**校准层**按课型记系数，不改基线公式。判据与做法见 `individual-calibration.md` §5。
3. **不把模型输出当计划生成器。** 计划由训练学规则（周期化、排序阶梯、间隔与恢复）决定，模型只在候选里排序。两层顺序不可倒：先规则筛合法落点，模型只在合法集合内排序。
4. **不把「参数会变」当作弃用理由，也不把参数固化当校准目标。** 见 §0.4。

### 0.3 参数为什么变不影响结论

A 的强度项是 `重量 / 参考 1RM`。注意 ref **整体平移**时会发生什么：

- 所有动作的相对强度**同比变动 → 排序完全不变**
- 只有 ref 之间的**相对关系**变了，排序才会动

例：参考深蹲与卧推的 1RM 各自上调几个公斤，动作库排序不动；但「暂停深蹲相对主项深蹲的比重」从 0.85 掉到 0.78，排序会动。

→ **参数漂移是信号，不是噪声。** 参考 1RM 值得校准，理由不是让绝对值更准，而是捕捉「某个变式相对主项在退化」——这类信息比任何量表都早。**校准的对象是 ref 之间的关系，不是刻度的绝对值。**

### 0.4 三层的分工

| 层 | 负责 | 不负责 |
|---|---|---|
| 训练学规则 | 生成候选落点、判定合法性 | 不知道你的疲劳余量 |
| 应激模型 | 在合法落点间排序、算清代价转移 | 不知道休息、动机、睡眠、肌糖原、技术退化 |
| 训练者体感 | 疲劳、动机、睡眠、状态 | 无法复算、无法审计 |

**缺一层都会出错**：只有模型 → 忽略规则和体感；只有规则 → 看不见局部代价转移；只有体感 → 无法复算、无法审计。最常见的失败是**把体感到的现象当成模型能解决的问题去问模型**——例如"深蹲若干组后引体就是做不动"，而模型看不见等长稳定负荷（盲区②），这类问题只能由训练学规则与体感裁决。

### 0.5 它是基线层，不是个体校准的终点

模型分两层：**基线层**（本文件 + `scripts/session_strain.py`，任何人拿到就能跑，只支持结构性的结论）与**校准层**（使用者自己的参考 1RM、时长口径、课型 sRPE 基线、单次上限，落在使用者工作空间）。

要按自己的数据调整，走 `references/consultation/individual-calibration.md` 的校准阶梯（L1 参考 1RM → L2 时长口径 → L3 课型 sRPE 基线 → L4 单次 AU 上限 → L5 k 拟合可选），配套 `scripts/calibration_report.py` 判定当前数据支撑到哪一级。

**两者不可混改**：基线层只在发现方法层面错误时改（公式、系数、判据写错了）；校准层由使用者随时按自己的数据改。觉得读数不合意时先问是哪一层的问题——绝大多数是校准层缺数据或时长口径不一致，不是基线层算错。

### 0.6 与 §7 的关系

§7 给的是逐条可靠边界的量化依据。本节是读法总纲，冲突时以本节为准。

## 1. 它补的是什么洞

MRV 审计数的是「某肌群一周多少组」。它能回答"这块肌肉恢复得过来吗"，但答不了下面三件事：

| 现象 | MRV 审计给出的结论 |
|---|---|
| 8 组容量深蹲做完人整个缓不过来，后面引体上气不接下气 | 背部周组数没超 → 合规 |
| 卧推 + 窄距之后放 OHP，肩还有力气但三头顶不住 | 三头周总量守恒 → 看不出差别 |
| 同样的动作换个顺序，某个动作就是做不动 | 完全不涉及 |

三个现象都发生在**单次课内部**，而 MRV 是**周尺度的组数**。本模型把尺度收到单次课。

## 2. 输出什么

| 指标 | 抓什么 | 读法 |
|---|---|---|
| **A** 系统应激总量 | 这节课"整个人练完有多废" | 无量纲；只做课与课之间的比较 |
| **Rf** 峰值瞬时应激 | "最喘的那一刻" | 与 A 分开读，二者不等价（见 §4） |
| **penalty** 动作执行惩罚 | 这个动作排在这个位置打几折 | 1.0 = 完全新鲜 |
| **崩坏风险** | 疲劳下动作质量会不会走样 | = 技术需求 × 惩罚；≥1.6 高，≥1.2 中 |
| **协同比** | 目标动作开始前，它最吃的那块协同肌被刮掉多少 | ≥1.5 且协同深度 ≥3 → 链条受限 |

## 3. 模型形式

**单组基础应激**

```
L = m × (reps / 8)^0.75 × (%1RM / 70%)^1.6
```

- `m` 肌肉质量系数：参与的肌群越大越高（深蹲/硬拉 1.00，前蹲/相扑 0.85-0.90，卧推 0.50，OHP 0.40，孤立 0.08-0.15）
- 次数与相对强度都是幂函数，强度指数（1.6）高于次数指数（0.75）——同等组数下，把重量加上去比把次数堆上去更"贵"
- 自重/不可加载动作（引体、划船、夹胸、核心等）用等效强度系数 `eff`（0.40-0.75）替代 `%1RM`

**两池瞬时恢复**

```
Rf = F + S
F 快池：τ = 60 s，占 55%   心率 / 呼吸 / 酸性代谢
S 慢池：τ = 720 s，占 45%  通气偿还慢相 / 体温 / 代谢堆积
每组把 L_eff 按 55/45 注入两池，组间按各自时间常数衰减
```

单指数恢复（只留快池）会低估"8 组深蹲之后整段时间缓不过来"这件事，因为缓不过来的那部分不在心率上。

**累积放大**（把"过了某个点就崩"写成公式）

```
第 i 组的有效载荷  L_eff = L × [1 + β(1 − e^(−A/A_ref))]，β = 0.75，A_ref = 8
```

在已经消耗过的系统上做动作，代价超线性上升；但放大**有上限**（β 封顶）。线性放大在实测中会发散（后侧链动作的惩罚算到 6 倍以上），饱和形式才可控。

**时长**：组间休息取动作库默认值或输入覆盖；动作间默认 120 s（换器械、装片也计入）。A 为全程累积不衰减，Rf 只在课内衰减。

**顺序 → 起始 Rf 的反直觉效应**（由 A 累积 / Rf 衰减这一对性质直接推出）

"把一个动作往前挪"**不必然**降低它的起始 Rf。前移会跳过它前面那个动作，也就一并跳过了那个动作的组间休息——若丢掉的休息时间多于跳过的疲劳，起始 Rf 反而更高。

实测例（周一深蹲日 W3）：引体由「深蹲 5×8 + 暂停深蹲 3×8 + OHP 3×8 之后」移到「暂停深蹲之后、OHP 之前」，起始 Rf **1.17 → 1.33**（OHP 三组的组间休息本身在给系统恢复）。

→ 用法：**"放在新鲜时做"与"紧跟着做"是两件事**。用挪位置解决疲劳问题前先跑一次模型；要真正压低某动作的起始 Rf，**减它前面的总量比挪位置可靠**。

## 4. 为什么不合成一个数

用户最初的设想是"最终运算出一个数值"。按实测数据，合成会毁掉诊断能力：

**其一，系统轴与强度轴反向。** 把同一份 8 周计划的周一深蹲日逐周汇总，系统轴（容量 × 强度，A 的雏形）与强度代理轴（相对强度的高次幂，只算 %1RM 可算的杠铃主项）相关系数 **r = −0.58**：容量期系统轴到 96% 峰值时强度代理轴只有 34%，冲刺期（W8-9）反过来——强度代理轴 92% 峰值而系统轴落到 30% 上下。1:1 合成等于让两个信号互相抵消，整个周期被拉平，反而看不出"现在压我的是容量还是强度"。

> 强度代理轴**不在脚本里**：它只对 %1RM 可算的外部负重动作成立，自重动作（引体、划船）缺负荷数据，硬套会被高估。它目前只用于周期层面的对比分析。

**其二，A 与 Rf 不等价。** 动作多而轻的课（轻量日）累积项持续上涨，A 不低，Rf 峰值甚至反超重日；动作少而重的课 Rf 高而 A 未必高。"有多废"和"有多喘"是两个问题。

**其三，MRV 与这三根轴也不是一回事。** MRV 管周尺度肌群恢复，A 管课内系统预算，协同比管课内链条限制。三者会给出互相矛盾的结论（肌群组数合规但课内链条受限是常见组合），必须并列读。

## 4.1 系统轴与局部轴是两套账，不是同一根轴的两个读数

`simulate()` 算 A 与 Rf 时**不读链条档案**——系统轴只用 `m` / `ref` / `eff` 与时间常数。`chain_analysis()` 单独算局部等效组与协同比。两套账在代码层面就没有耦合。

⇒ **它们可以反向移动，而且实测确实反向过。**

实测：某一节课把一个高 `m` 的后侧链变式（暂停硬拉）换成中 `m` 的前蹲。

- 系统账：A 明显上升（换入动作的边际贡献约占增幅的 3/4）——`m` 与相对强度都更高
- 局部账：腿后侧与竖脊肌的**课内前置负荷下降**（前蹲不做髋伸），随后做的山羊挺身这类动作的局部代价减轻
- 训练者体感：整体变化不大，但山羊挺身明显更轻松

**三者都成立，不矛盾。** A 上升说的是"整节课的系统总账变贵"；山羊挺身更轻松说的是"局部链条变松"。系统总账变贵和某个局部动作变轻松可以同时为真。

**读法**：

1. **整体疲劳读系统轴，局部可完成性读局部轴。** 不要用系统 A 的变化去解释局部动作为什么变轻/变难。
2. **两轴冲突时先信局部体感。** 局部体感是训练者当天的真实体验，模型的局部档案本身已知不全（不含等长稳定负荷，见 §8 盲区②）。
3. **"整节课更累"是系统轴的说法，"某处更轻松"是局部轴的说法。** 两者都别改写成对方。

这条也解释了为什么模型的协同比与 A 的方向经常不一致——**它们本来就不是同一根轴**。

### 4.2 局部代价主导的课型：A 会系统性低估

§4.1 说的是机制，这里说的是**漏的是哪一类课**。

实测 8 节课（4 个课型 × 2 周）里出现了一个反例：模型把某个课型的 A 排成**全周最低**（第 8/8 位），实测 AU 却排**全周第二**。同期另一个课型相反——A 排中间、AU 排最低。

| 课型 | A 排名 | AU 排名 | 方向 |
|---|---|---|---|
| 大肌群高组数课 | 最后一位 | 第二 | **相反** |
| 动作多、每个都轻 | 中间 | 最后一位 | **相反** |

另外两个课型（主项单轴日、后侧链日）大致同向。**错位不是全局偏移，是特定课型的结构性问题。**

**哪些课会被低估：**

1. **大肌群 + 高组数、但循环代价不高**的课。卧推类、划船类、坐姿拉举类——单组不累，
   但组数堆上去之后局部酸胀极强，心率却上不去（实测出现过「主观 +1 档、心率 −8%」）。
2. **动作数量多、每个都轻**的课。它们拉长了总时长，但没有任何一个动作构成系统负荷。
3. 反过来，**高 `m` 的单轴课**（大重量低次数的拉类）偏差较小——它的系统代价确实高，A 抓得住。

**为什么模型必然漏这一类：** A 走系统轴，用 `m`（动作张力）× `ref`（相对强度）× 时间常数
积分。局部代价不进这个式子——这类课的 `m` 不高，所以 A 不高，但 sRPE 会诚实地报出更高的档位。

**读法：**

- **跨课型比 A 的大小没有意义。** 上表里 A 排最后的那节课实测代价排第二。
  跨课型只比「同一课型内的相对变化」，这才是模型有效的那一层。
- **A 低不代表这节课轻松。** 看到某个课型的 A 明显低于其他课型时，先问一句
  「这是大肌群高组数课吗」——是的话，A 的低估是结构性的，不是读错了。
- **跨课型要排序，用 sRPE 或 AU，不用 A。** 这不违反 §0 的禁令：模型与体感分工不同，
  模型的强项是同课型内的结构比较，不是跨课型的绝对量级断言。

## 5. A% 相对刻度（现在就能用，不需要标定）

A 没有物理单位，但在同一份计划内可比：

**A% = A / A_anchor × 100**，A_anchor = 一次**已完成且恢复过来**的训练课

| A% | 读法 |
|---|---|
| ≤ 60 | 有余量，可以加 |
| 60 - 85 | 正常 |
| 85 - 100 | 接近已验证的恢复上限：只重排，不净增 |
| > 100 | 未验证区。不是"危险"，是"没做过，不免费" |

脚本不带默认锚点：不传 `--anchor` 时以输入文件中最高的一节课为 100，报告会标注这是**文件内相对刻度**。别把它当绝对阈值用。

## 6. 参数的三层来源

参数从低到高覆盖：**内置估算值** < `--params` 参数文件 < 输入文件内嵌 `params`（命令行 `--beta` / `--a-ref` / `--anchor` 最高）。

| 来源 | 何时用 | 标记 | 能支撑什么结论 |
|---|---|---|---|
| **内置估算值** | 起步阶段（暂无数据） | `estimate` | 只支持**同一份文件内**的相对比较 |
| **sRPE 标定值** | 攒够足够记录且通过校准阶梯门限后 | `calibrated` | 可给"这次过了"的单次上限阈值 |
| **用户自备参数** | 用户已有长期参数集 | `user` | 取决于用户数据质量 |

`source` 字段由脚本打在报告里；改成非 `estimate` 后，"估算参数只支持相对比较"的提示会自动消失。**这个标签是给读数的人看的——它不改变数值，只改变你能从这个数值推多远的结论。** 标一个 `calibrated` 却没通过门限，比不标更危险。

参数文件可覆盖模型参数（`params`）、各项 1RM（`one_rm`，用动作库 key）、单动作系数（`catalog`）。校准层产物落在使用者自己的参数文件里，不回写基线——见 `references/consultation/individual-calibration.md` §5。

```bash
python scripts/session_strain.py --init-params my-params.json    # 导出可编辑模板
python scripts/session_strain.py --input session.json --params my-params.json
```

## 7. 可靠边界（读结论前先看这段）

### 7.0 分辨率：先约定这把尺子读到哪一位

模型的**有效分辨率取 1%**。两个理由：

- 跨**全部可能排列**实测，A 的极差 <1%（周三 5 动作 120 种 <0.2%，深蹲日 7 动作 5040 种 <0.7%）。
- 参数本身的不确定度是 **±100% 量级**（同一套数据换三组参数，训练日之间的比值从 2.0x 到 3.9x）。

所以脚本输出里 A 的小数位是**运算过程的精度，不是模型的精度**。读法约定：

1. **A% 只读整数刻度**，不比较小数位。
2. **差异 <1% 一律判为"相等"**，不做"谁高一点"的推断。
3. 差异 ≥1% 才值得当结论说出口；≥10% 才值得当作决策依据。

这条约定不是掩盖误差，而是把结论锁在能站住的那一格上。它的直接后果：**"顺序不影响总量、只转移代价"在模型分辨率内严格成立**。

### 7.1 可信——排序、比值、余量分布、转移代价

- **顺序只转移代价，不改变总量**：周三 5 动作 120 种排列，A 极差 0.19%；深蹲日 7 动作 5040 种排列，极差 0.70%——都在 1% 分辨率以内。数学上不是严格恒等（放大项是凹函数，顺序有二阶影响），但**在读数精度内就是恒等**。**推论：把某个动作往前挪改不了这节课的总账，只改谁挨罚。** 所以"要么 A 动作做不动、要么 B 动作做不动"是求和式决定的，不是巧合。
- **同一批参数下，训练日之间的对比方向稳定**：三轮参数迭代中，深蹲日/卧推日的对比方向没变过。

**不可信——绝对阈值**

- 三组不同参数给出周一/周三 2.0x / 2.4x / 3.9x 三种幅度：**结构稳、幅度不稳**。阈值只能来自实测。
- 对"动作多而负荷轻"的课会**高估**：累积项持续上涨，Rf 峰值反超重日。这是 A 与 Rf 必须分开读的原因。
- 协同比在**故意改变协同模式的变式**上会假阳性：窄距卧推的限制环节被判成"胸"、前蹲被判成"核心"——那是变式的设计意图（把该肌群排除），不是缺陷。承担比例是工程参数，只用于同一节课内部的相对比较。
- 参数不稳定时，**跨计划的绝对值对比没有意义**（换了动作库系数、换了 1RM，A 不可直接比）。

## 8. 排期决策顺序

1. **看 A%**：余量最大的那天才能接新动作。全周都接近上限 → 是净增问题，不是排期问题。
2. **看 penalty 与崩坏风险**：技术需求高的动作（高翻 1.00、硬拉 1.00、深蹲 0.90、引体 0.80）不排在惩罚 >1.5 之后。
3. **看协同比**：主项与弱项动作不应落在"链条受限"位置——局部链条受限会让动作练不到目标肌，这类代价和系统折扣不是一回事（系统折扣对"运动能力项"可接受，链条受限不可接受）。
4. **区分重排与净增**：A 差在分辨率内（<1%）→ 重排，只是转移代价；A 上升 ≥1% → 净增。前者可以放开调，后者必须回到 MRV 与恢复预算。

> ⚠️ **这四步是"在候选里排序"，不是"生成候选"**：合法落点先由训练学规则决定（单日排序阶梯、同肌群/同模式间隔、等长脊柱负荷不排硬拉日或其次日）。**模型读数好但违反规则的位置直接排除**，不做例外。
>
> 模型有四处盲区，遇到时以训练学判断为准：**① 不追踪握力**（农夫行走 ↔ 引体这类由握力决定的顺序，模型会给出反向建议）；**② 链条档案不含等长稳定负荷**（深蹲的链条不登记上背，故深蹲日之后的拉类动作被低估）；**③ A 不惩罚时长**（迁移可让 A% 几乎不变而时长从全周最短变最长）；**④ 不追踪速度需求**（td 是崩坏代价而非速度衰减敏感度，爆发类与补量类的 td 差可能只有 0.1，模型信号微弱；但顺序由训练学规则明确——速度主导动作不能排在任何人之后）。
>
> 完整的排序阶梯、跨日约束、盲区处置与实测案例见 `references/planning/exercise-placement.md`。

## 9. 脚本入口

```bash
python scripts/session_strain.py --input session.json            # 多方案并排对比
python scripts/session_strain.py --input session.json --curve    # 逐组曲线（看 Rf 峰值出现在哪一组）
python scripts/session_strain.py --input session.json --json     # 结构化输出
python scripts/session_strain.py --anchor 12 --demo              # 指定锚点 / 跑自带样例
python scripts/session_strain.py --list                          # 动作库 key
```

个体校准（按使用者自己的数据调整模型）用另一个入口：`scripts/calibration_report.py`，见 `references/consultation/individual-calibration.md` §3。

输入格式见 `scripts/examples/session_strain_sample.json`（该文件自带一套示意 1RM，可直接 `--demo` 跑）：`sessions[].blocks[]` 只需 `exercise`（动作名）/ `sets` / `reps`，**外部负重动作另需 `weight`**；`rest` 与 `work_per_rep` 有动作库默认值，可覆盖。**外部负重动作的参考 1RM 必须在输入里用 `one_rm` 给出**——动作库不预置。

**审计脚本必须与计划同步**：审计一份**已实施**的计划时，生成训练课的脚本（把计划文本转成 blocks 的那一层）必须与计划当前版本一致。改了计划却没改脚本，报告会继续审计一个已经不存在的计划——且因为它"看起来对"（数字都变了、结构也对），很容易被忽略。改动计划后，同步跑一次审计并比对前后读数。

## 10. 动作库：怎么写名字、怎么加动作

### 10.1 动作名

`exercise` 字段接受三种写法，脚本自动归一成动作库 key：

| 写法 | 例子 |
|---|---|
| 库内 key | `squat` / `dl_sumo` / `rdl` / `cg_bench` |
| 中文名 | `深蹲` / `相扑硬拉` / `窄距卧推` / `引体` / `实力推` |
| 常见英文写法 | `deadlift` / `bench press` / `pull up` / `RDL` / `close grip bench` |

匹配不上时**报错并给出最接近的候选**（如 `squatt` → "是想写 squat / pause_squat / front_squat 吗"），不会静默取错动作。这比"猜一个最像的"更安全：排期结论依赖具体动作，取错动作比报错糟得多。别名表在 `scripts/session_strain.py` 的 `ALIASES`，加条目即可扩充。

### 10.2 库里没有的动作

**不必改脚本**——在输入 JSON（或 `--params` 文件）里用 `catalog` 新增：

```json
"catalog": {
  "muscle_up": {
    "zh": "双力臂", "m": 0.45, "eff": 0.85, "td": 0.85,
    "rest": 150, "wpr": 2.5,
    "chain": {"lats": 0.75, "biceps": 0.55, "upper_back": 0.40},
    "prime": "lats"
  }
}
```

| 字段 | 必填 | 含义 |
|---|---|---|
| `m` | ✅ | 肌肉质量/系统负荷系数（1.0 ≈ 深蹲、硬拉量级） |
| `td` | ✅ | 技术需求 0–1，疲劳下动作质量崩坏的风险权重 |
| `ref` | 二选一 | 有外部负重：参考 1RM 的绝对重量（可被 `one_rm` 覆盖）。内置动作库**不预置**该值，见下方说明 |
| `eff` | 二选一 | 自重/不可加载动作的等效强度 0–1 |
| `zh` | | 显示名，缺省用 key |
| `rest` / `wpr` | | 组间休息秒 / 每次用时秒，缺省 90 / 3.0 |
| `chain` + `prime` | 成对 | 各肌群承担比例 + 主动肌；**给了其一必须给另一个**，否则协同比算不出来，脚本直接报错而不是硬凑 |

`catalog` 对**已登记动作**是调参（可只给部分字段），对**新 key** 是新增——同一段配置里两种用法都支持。

> **内置动作库不带参考 1RM**。库里 14 个外部负重动作（深蹲 / 暂停深蹲 / 前蹲 / 传统硬拉 / 相扑硬拉 / 暂停硬拉 / RDL / 早安式 / 卧推 / 窄距卧推 / 暂停卧推 / OHP / 高翻 / 高拉）**没有默认 1RM**——它们的相对强度 = `weight / ref`，`ref` 必须由调用方给出（`--params` 的 `one_rm` / 输入 JSON 的 `one_rm` / `--init-params` 导出的模板）。缺 `ref` 时脚本报错并给出补法示例，**不会静默拿一个默认值去算**。
>
> 只带 `eff` 的自重动作（引体 / 划船 / 夹胸 / 面拉 / 农夫行走 等）不受影响，它们的强度来自等效系数而非 1RM。

**`prime` 的选取规则**：`prime` 是**训练意图上的目标肌**，通常应取 `chain` 中承担比例最高者。两者不一致时，协同比会把承担最多的那块肌当作"协同肌"去算比值，判读会自相矛盾（例：山羊挺身的 `prime` 若标成腘绳，而 `chain` 里竖脊承担 0.75，它每次都会被判成"链条受限：限制环节是竖脊"——那正是它要练的肌）。

有意的例外要在 `chain` 旁的注记里写明理由，目前有两处：
- `row`：`prime=upper_back`（0.52），而 `lats` 系数略高（0.55）——划船的训练意图是上背，属有意标注。
- `goodmorning`：`prime=hams`（0.60），而 `erectors` 系数更高（0.80）——早安式的竖脊是等长稳定、髋伸才是目标；因此它出现在深蹲日之后时被判"链条受限：限制环节是竖脊"是**有效结论**（躯干先疲劳，腘绳没被练到），不是缺陷。

### 10.3 缺 `chain` 档案的后果（会显式提示，不静默降级）

- **照常算**：A、Rf 峰值、执行惩罚、崩坏风险只依赖 `m` / `ref` / `td`，与链条档案无关。
- **不算**：该动作不计入"课末肌群等效组"，协同比列为 `n/a`，报告顶部打出 `⚠ 无链条档案` 提示。

看到那条提示就知道**等效组被低估了**，别拿被低估的等效组去和 MRV 比。缺档案的动作如果长期要用，把 `chain` / `prime` 补上。
